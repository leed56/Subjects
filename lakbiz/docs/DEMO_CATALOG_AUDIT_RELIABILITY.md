# Demo catalog audit — transient source recovery

Audit run [218](https://github.com/leed56/Subjects/actions/runs/38149385314) failed its quality validation on 11 October 2026. SPAR2U returned temporary HTTP 503 responses for a collection page and four product detail pages. Only 154 of 158 truncated listing names were hydrated; the resulting pharmacy/grocery catalog contained five truncated names, which the unchanged strict validator correctly rejected. No import occurred. The next unmodified acquisition in [run 219](https://github.com/leed56/Subjects/actions/runs/38151635517) passed; this was transient source availability, not an accounting migration failure.

Public source requests now use at most three attempts for HTTP 429/500/502/503/504, network failures and aborts, with a 20-second per-attempt timeout and exponential backoff. Valid Retry-After seconds or HTTP dates are respected within the existing 30-second cap. Persistent rate limiting no longer recurses without a bound. Each retry passes through the existing request throttle. Existing robots checks remain in front of the helper; 401/403/404 responses are not retried. Optional exhausted sources are logged and skipped as before, while required sources still throw. Quality/coverage validation still fails when any truncated identity remains; no names, coverage or provenance are fabricated or relaxed.

The first retry-enabled acquisition, [run 220](https://github.com/leed56/Subjects/actions/runs/38156794480), exposed persistent 429 responses on five product pages after retry exhaustion. The rate-limit default cooldown is now 5 then 10 seconds rather than the 1 then 2 seconds used for server/network errors. Any still-unresolved truncated or blank names are partitioned into a separate `*.quarantine.json` report **before** either grocery normalization or pharmacy fallback selection. These are rejected source candidates, not accepted catalog products. Published source counts and all unchanged minimum coverage thresholds apply to complete accepted rows only. The catalog summary exposes the exclusion count and reason totals; the separate report preserves source IDs, URLs, original incomplete names and retrieval timestamp for review. No title is guessed from a URL. The workflow uploads the public catalog and quarantine diagnostics even if later validation fails; missing files only warn at the upload step, while the failed acquisition/validation step still fails the job.

The normal Vitest configuration now discovers the previously excluded `scripts/demo-catalog/**/*.test.mjs` fixtures. This uncovered two existing taxonomy errors, now corrected: plural snack tokens such as “biscuits” in the pharmacy retail filter, and the specific Munchee Milk Short Cake product name being routed to bakery. The specific name exception is supported by [CBL's own product history](https://www.cbllk.com/cbl/public/index.php/our-history); generic cakes retain their existing bakery classification. Explicit non-convenience grocery exclusions retain precedence.

Verification: all 363 tests across 49 files pass, including transient recovery, exhausted retries, rate limiting/date handling, access-denied non-retry, request timeouts, quarantine conservation/provenance, exclusion from both industry payloads, strict title parsing, catalog classification, source identity and importer fixtures. Changed catalog files and test configuration pass ESLint; acquisition/helper scripts pass Node syntax checks. No dependency, live database, user, industry demo or accounting activation was changed. The public-source acquisition workflow on the new commit remains the integration check; passing local fixtures is not proof that every upstream site will be available on every run.
